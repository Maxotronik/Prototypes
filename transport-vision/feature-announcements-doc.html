01 · Background
The Problem

When new features or product changes ship, users don't learn about them until they stumble across them — or until they call support. There's no systematic way to communicate what changed, what's new, or what they should try. Carriers and dispatchers miss features that would save them time; buyers and sellers don't know improvements were made on their behalf.

The Feature Announcements system is a structured way to inform users about product changes at the right moment, in the right format, without being intrusive. It spans all surfaces of the transport platform — Loadboard, Manage page, Hub — and supports multiple delivery channels per announcement.

02 · Announcement Types
Content Categories

Each announcement belongs to one of three content types. The type determines how it is labeled in the What's New panel and history log, and informs the editorial tone of the announcement copy.

TypeBadgeWhen to use
New Feature New Feature A capability that did not previously exist on the platform. Examples: Compare Jobs, Instant Book, Release Slip.
Improvement Improvement An enhancement to an existing feature or interaction. Examples: filter bar reorganization, price per mile display, card redesign.
Release Note Release Note An informational change that doesn't require user action — policy updates, minor visual changes, backend improvements that affect data freshness. Appears in What's New only (no modal, no tooltip).
03 · Delivery Channels
How Announcements Reach Users
crop_square Modal (blocking)
  • A full-screen overlay that appears after page load (700ms delay). Blocking — the app is not interactable until the modal is dismissed.
  • Used for high-impact announcements only. The modal communicates priority.
  • Supports a carousel: multiple announcements shown in sequence. Starts from the oldest unseen; the last step changes "Next" to "Done / Close".
  • Dismissing with X marks the current and all prior announcements as read. Announcements not yet reached remain unread.
tips_and_updates Tooltip / Callout (contextual)
  • Anchored to a specific UI element. Fires when the user arrives at the relevant surface — not on login.
  • Non-blocking. Any click outside the tooltip dismisses it automatically.
  • Two trigger modes: contextual (fires when the user navigates to the relevant area) and hover (fires once when the user hovers a specific element).
  • Can be chained: the same announcement contains multiple tooltip steps the user navigates through with Next / Dismiss.
  • Fires once per session. A tooltipFired flag prevents re-triggering on the same page.
inbox What's New only (passive)
  • Appears only in the What's New panel. No active push via modal or tooltip.
  • Used for Release Notes and lower-priority improvements that don't warrant interruption.
  • The panel is the user's inbox — they access it when they choose to.
04 · Journey Map
Delivery Journeys
Journey 1 — Login with pending modal
  • Modal appears 700ms after page load (blocking overlay).
  • Carousel starts from the oldest unread announcement.
  • Closing with X marks the current and all prior announcements as read.
  • Announcements expired by date are skipped even if unread.
Journey 2 — Navigation to a contextual tooltip area
  • Tooltip fires when the user navigates to the relevant surface — not immediately on login.
  • Dismissed by any outside click. No explicit close button needed.
  • One-time per session. If the user navigates away without interacting, the tooltip is considered seen for that session.
  • Chained tooltips: user must navigate all steps for the announcement to be marked as read. Returning to the area restarts from step 1.
Journey 4 — Modal + Tooltip (same announcement, two phases)
  • Modal fires on login (J1 rules). Tooltip fires when user reaches the relevant surface — independently of whether they completed the modal.
  • The modal marks the announcement as read. The tooltip is contextual reinforcement, not a read condition.
  • What's New shows a single entry for the announcement. Clicking it opens the modal version, not the tooltip.
Journey 5 — User opens What's New manually
  • Panel toggle opens/closes with the What's New button in the header.
  • Clicking an item opens the detail modal (non-blocking when opened from the panel — user initiated it).
  • Opening the detail is what marks the item as read — the panel list view does not.
  • Each item is independent. No Previous / Next navigation between items in the detail view.
05 · Push Rules
When & How Announcements Are Pushed
  • One at a time — announcements are queued. Never show two simultaneous pushes (modal + tooltip at the same time).
  • Context first — tooltips only fire when the user is in the relevant area. A tooltip about the Manage page filter bar does not fire on the Job List.
  • Modal before tooltips — if both a modal and a tooltip are pending, the modal fires first (on load). The tooltip fires afterward on contextual navigation.
  • No re-fire within a session — each push channel fires once per session max, controlled by flags (tooltipFired, read state per announcement).

imgHtml — contextual image

Announcements that have an associated tooltip can optionally include an imgHtml block: a static mockup of the UI that the announcement refers to. When the user opens the announcement from the What's New panel, this image is shown in the detail modal — giving them context without requiring them to navigate to the relevant area. The tooltip itself still fires contextually when they arrive at the area organically.

07 · What's New Panel
The In-App Inbox
Panel structure
  • Lists all HISTORY entries from the past year, ordered by launch date (most recent first).
  • Each item shows: announcement title, short description, and an unread dot if unseen.
  • Tooltip steps from chained announcements appear as separate items in the panel, with a tips_and_updates icon to distinguish them from full announcements.
  • Clicking a tooltip item fires that specific tooltip step directly — without opening the modal first.
  • Type badges (New Feature / Improvement / Release Note) are not shown in the panel list. They appear in the detail view only.
Read state
  • An announcement is marked read when the user opens its detail modal — not when it appears in the panel list.
  • Opening the detail from the panel fires any associated chained tooltip chain once the modal is closed (if not already fired).
  • The header badge shows the count of unread items.
History duration

The panel shows all announcements from the past 12 months. Items older than 1 year roll off. There is no "View all" button unless the list exceeds 12 items — at which point a scroll + View All flow handles the overflow.

09 · Open Questions
Decisions Still Pending
  • What defines a "new user"? — A threshold combining account age (in days) and number of completed jobs. The exact values are not yet defined.
  • Modal / tooltip trigger event — Currently prototyped as firing on page load / new session. Needs confirmation from dev on what constitutes a "new session" (tab open, login, refresh).
  • Tooltip behavior when user never reaches the relevant area — Edge case: if a tooltip is tied to a surface the user never visits in the expiration window, it never fires. Handled case-by-case: if the content is critical, use "user dismiss" expiration; if the surface is commonly visited, a long expiration window is sufficient.
  • History detail view structure — The detail modal from What's New reuses the existing announcement modal. The layout for announcements that have both a modal body and a tooltip step (J4) is still being defined.
