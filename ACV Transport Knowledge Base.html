ACV Transport Knowledge Base

A consolidated reference covering ACV Transport's product offering, mechanics, personas, and workflows. Synthesized from internal product documents (2022–2024). Last updated: April 2026.

Section 1

What Is ACV Transport

ACV Transport is ACV Auctions' vehicle transportation service, connecting dealers (shippers) who need vehicles moved with a vetted network of carriers. It operates as a managed logistics layer — ACV handles job posting, carrier matching, dispatch, and issue resolution, so dealers don't have to manage carriers themselves.

For Shippers
  • Trusted, vetted carrier network
  • Predictable pricing with locked-in quotes
  • End-to-end visibility from request to delivery
  • ACV resolves issues directly with carriers — dealers don't have to
For Carriers
  • Centralized job board with posted pricing
  • Flexible booking (offer or instant book)
  • Performance tiers that unlock better job access
  • Real-time job assignment notifications
Section 2

Transport Product Types

ACV Transport offers several distinct products depending on the context of the vehicle move and who is initiating it.

2.1

Auction Transport (Standard)

The baseline product. When a buyer wins an ACV auction, they can select ACV Transport at checkout to move the vehicle from the seller's location to their dealership. This is the core attach product and the primary volume driver.

  • Priced at checkout before the buyer confirms
  • Carrier is sourced from ACV's loadboard network
  • Shipper tracks status through the transport hub
2.2

Off-Platform Transport

Allows dealers to ship any vehicle not tied to an active ACV auction — including vehicles sourced from other auctions, marketplaces, or any other origin. Orders are created entirely online through the ACV app.

How it works:

  • Shipper enters one or multiple VINs per order — each auto-populates make, model, and year
  • All vehicles in an order must share the same pickup address, delivery address, and type of transport
  • An instant quote is generated and locked in
  • Oversized vehicles trigger a prompt to call ACV Transport instead
  • Shipper tracks all orders alongside their auction transport orders

Primary use cases in priority order:

  1. Auction to Dealer — vehicles purchased at non-ACV auctions (~10M units/year TAM)
  2. Dealer to Auction — moving vehicles to physical auctions or storage
  3. Dealer to Consumer — shipping purchased vehicles to end buyers
  4. Consumer to Dealer — trade-in transportation
~13K dealersTAM — active dealers with ACH on file
~30K units/moAt 50% penetration
Payment: ACH only. Only dealers with ACH on file can use this product.

Dealer-Facing Interface

Two surfaces in the ACV Transportation tab:

  • Request Transportation — A multi-step form to create a new transport request. Step 1 collects: VIN, Make, Model, Year, INOP (yes/no), Pickup Address, Delivery Address. Available to dealers with ACH on file who already have a high transport take rate and volume.
  • View Requests — A status dashboard listing all transport requests. Columns: Order ID, VIN, Vehicle, Distance, Delivery ETA, Status. Statuses include: Posted, Dispatched, Picked-up, Delivered, Hold, Cancelled (by ACV).

UX and product notes from spec:

  • Order ID is a synthetic (fake) Auction ID generated for non-captive requests — not a real ACV auction order
  • Kebab menu on each row includes "Download BOL"
  • Export Data option at the top of the list (consistent with other app pages)
  • Delivery ETA edge case: if the ETA date is in the past, do not show the date — display "Updating" or "Delayed" instead
  • Non-auction support contact shown on page: transport@acvauctions.com (dedicated phone and email, separate from regular auction transport support)
  • Risk flagged in spec: increased inbound call volume expected when statuses change or delays occur
2.3

Expedited Transport Discontinued

This service is no longer offered. The content below is retained for historical reference.

A premium tier giving shippers the choice between speed and price on each vehicle they ship.

  • Costs 10% more than standard rates — the premium is passed directly to carriers as incentive
  • Tighter pickup and delivery SLAs apply
  • If not delivered by the guaranteed date, the additional cost is automatically refunded as Transport Credits
Presenting three options (Expedited / Standard / No Transport) leverages Middle Option Bias — dealers who previously declined are more likely to choose Standard when it's framed as the middle option. Estimated attach impact: 1.5%–3% increase.
Payment: ACH only.
2.4

Seller-Required Transport (Mandated Transport)

Gives sellers the option to require that ACV Transport handles all pickups on their auctions — buyers cannot arrange their own carrier.

Why it exists — buyer-arranged transport leads to significantly worse outcomes:

  • 5× more likely to cause significant pickup delays
  • 2.5× longer to resolve abandoned vehicle cases
  • ACV Transport abandonment rate: ~0.6% vs ~3% for buyer-arranged

Seller options:

  • Mandate ACV Transport for all vehicles launched
  • Mandate only for vehicles launched from residential addresses

Target segments: sellers launching from residential addresses (CarBuyerUSA, SwapALease, AllCars), new OEM/channel partners, current Lot Sweep partners, and sellers with abandoned vehicle rates above 15%.

Job Lifecycle & Transportation Statuses

Every ACV transport request moves through a defined set of statuses from creation to completion. These statuses are visible to shippers in the transport hub and managed by carriers and ACV operations.

Status What It Means
Awaiting Release Request processed; waiting for payment to clear and release slip to be generated
Hold Job paused while an issue is resolved, or per Sales/Customer request
Ready to Post Job is ready to be posted to the job boards
Posted Job is live on ACV's Transportation Portal and/or 3rd-party load boards (e.g. Central Dispatch)
Locked A transport admin has locked the job while negotiating with and assigning a carrier
Staged A carrier has flagged interest and is building their load; carrier has 15 minutes before the job is released back to the board
Pending Offer A carrier has submitted an offer; Transport Operations reviews and dispatches if details are in order
Accepted (Dispatched) Carrier is assigned; scheduled pickup and delivery dates are confirmed
Picked Up Vehicle is on a truck and in transit
Delivered Vehicle has been delivered to the destination

Cancelled by Transporter Assigned carrier cancelled; ACV Operations will review, resolve issues, and reassign
Cancelled by ACV Job cancelled by ACV; no longer active

Key lifecycle notes:

  • The Staged window is 15 minutes — a temporary hold while the carrier evaluates and potentially bundles the job with nearby work
  • Pending Offer is not automatic — a human dispatcher reviews and approves or rejects before a job is dispatched
  • Instant Book skips the Pending Offer review and immediately moves the job to Dispatched status
  • When a carrier cancels, the job returns to the board and ACV Operations takes over resolution
Section 5

The Loadboard (Carrier-Facing)

The ACV Loadboard is the carrier-facing portal where carriers find, book, and manage transport jobs. It is separate from the dealer-facing ACV app.

5.1

Onboarding

Carriers sign up via Auth0 (email/password or Google). After creating an account they enter:

  • Required: Name, company name, phone, email, address
  • Optional: DOT number, MC/MX number

New accounts are held at a "new account" page until a Transport Admin reviews and activates them. An email is automatically sent to Transport Managers and Carrier Operations when a new carrier signs up. Once activated, carriers must accept Terms of Service before accessing the platform.

If a carrier needs to be linked to an existing company (e.g. a new driver joining an established carrier), they contact Transport Operations directly.
5.2

Finding Jobs

The Available Jobs page is the default landing page after login. Carriers browse and filter open jobs here.

  • Filters: Date range, pickup state, delivery state, VIN, or Order ID
  • Sorting: Job ID, Order ID, Job Date, Inop status, Pickup/Delivery state and zip, Distance — default is Job ID ascending
  • Pagination: 50, 100, 250, 500, or All jobs per page
  • CSV export: All available jobs can be downloaded; filters and sorting do not apply to the export
Filters and sorts require clicking Apply — results are not dynamic or real-time. Hidden checkboxes and server-side validations prevent bots from staging jobs.
5.3

Booking a Job

Booking happens in two steps: Stage → Offer or Instant Book.

Step 1 — Staging

Carrier selects one or more jobs and clicks "Select Jobs." The job is temporarily held for 10 minutes — no other carrier can see or stage it during this window. If no offer is submitted in time, the job is automatically released back to the board.

Step 2a — Making an Offer

On the Staged Jobs page, the carrier enters a pickup date, delivery date (defaults to ACV's suggested date based on distance SLAs), and payout (defaults to the posted asking price). The offer enters Pending Offer status and is reviewed by Transport Operations, who either accept (job moves to Dispatched) or reject (job returns to the board).

Step 2b — Instant Book

Carrier selects the Instant Book option and books at the posted asking price. The job is immediately set to Dispatched — no ops review required. Date validations still apply.

Validations prevent: dates in the past, delivery before pickup, delivery beyond the max SLA window. Carriers can stage and book multiple jobs simultaneously, submitting individually or all at once with "Submit All."

Key documents:

  • Dispatch Sheet — agreement between ACV and the carrier covering vehicle, location, and payment details; includes contract terms
  • Release Slip — authorization document for the carrier to pick up the vehicle; contains a secret phrase the driver presents to the shipper as proof of authorization
  • eBOL (electronic Bill of Lading) — legal delivery receipt describing the vehicle and its condition; required for carrier payment to be issued

Notification Engine

Launched December 2022. A real-time event-driven system that sends emails to shippers and carriers as key status changes happen — no manual trigger required. Before this system, both parties had to log in or call ACV to get status updates.

Shipper Notifications

Carrier Notifications
  • New job assigned — carriers previously had to log in to discover new assignments

Checkout Experience (Shipper-Facing)

The transport checkout is the moment buyers decide whether to attach ACV Transport when winning an auction. Low-information decisions at this step were driving unnecessary rejections.

Problem

Why Buyers Were Declining

Buyers often declined transport impulsively — handing the job to a local carrier or posting to Central Dispatch — without understanding ACV Transport's value. They also couldn't easily see an all-in price because no delivery address was pre-selected.

Solution

Checkout Experiments (Launched February 2023)

Four changes were tested via A/B experiments, feature-flagged and targeting low and mid attach dealers:

1
Additional reject content When a dealer declines transport, additional content surfaces highlighting the value props they're giving up
2
Opt-in by default Transport is pre-selected so buyers see the all-in cost before making a decision, rather than having to opt in to see the price
3
Confirmation of opt-out If a buyer still wants to decline, they're asked to confirm they understand what they're missing
4
Default delivery address When a dealer has multiple saved addresses, the cheapest-quoted address is pre-filled — previously no address was selected, blocking the quote display entirely
Impact

Projected Results

$3M–$6MProjected annualized revenue

Exploration

Fuel Surcharge in Checkout

A design exploration (checkout.html — Tab 04) testing how a variable fuel surcharge would surface at checkout without disrupting the existing pricing structure.

How it works

A fuel surcharge is a variable percentage fee (currently 6.3%) applied on top of the base transport price. It fluctuates based on national fuel index data and is adjusted periodically. The surcharge applies to truck-based services only — Drive My Car transport is excluded and remains a flat fee.

Design decisions

  • Surcharge shown as a dollar amount, not a percentage. Buyers don't need to do math. "+$5.29" is more actionable than "+6.3%".
  • Banner positioned below the service selector. The surcharge amount depends on which service is selected — it updates dynamically when the buyer switches between Open and Enclosed transport.
  • Total in the header includes the surcharge. The price shown at the top right is always the true all-in price (base + surcharge). No separate "surcharge" line in the header — one number, one truth.
  • Discounts still visible in the service cards. The "was" strikethrough price is preserved per service row so buyers can still see the discount. The header does not show a "was" price — the surcharge makes the math ambiguous.
  • Drive My Car: flat $75, no surcharge. This service type is driver-operated; fuel cost is absorbed differently. The banner does not update when DMC is selected.
  • Banner style: info-level, not warning. Same visual treatment as the pickup address info box — blue background, info icon, single line. The surcharge is a cost of doing business, not an exception or alert.

Section 10

Business Metrics

Transport is one of ACV's most significant revenue contributors, representing a meaningful share of total company revenue. Because of the high revenue multiple at which the business is valued, even incremental improvements to transport performance have an outsized effect on overall company value. The three primary KPIs that drive transport's financial performance are Take Rate, Spread, and Cycle Time.

Source: Internal "Transport Business Metrics" document (2021). Directional analysis only — specific figures have been removed. External factors — auction market conditions, seasonality, gas prices — affect all metrics.
10.1

Take Rate

The percentage of ACV Auctions where the buyer selects ACV Transport at checkout.

  • Formula: Volume = Take Rate × Total Auctions
  • Why it matters: Higher take rate means more vehicles flowing through ACV Transport, increasing total revenue. Dealers who use more ACV products show higher retention and lifetime value. Transport also reduces unwind and abandoned vehicle rates, benefiting the broader marketplace.
  • Impact: Even a single percentage point improvement in take rate generates meaningful incremental revenue and compounds significantly at scale across total auction volume.

Roadmapped levers: more attractive checkout experience (+2%), better pricing modifiers for lane/dealer/vehicle type (+3%), buyer delighters like tracking and status updates (+1%), reduced cycle time (impact TBD).

10.2

Spread

The difference between what the buyer is charged and what ACV pays the carrier. This is ACV Transport's per-vehicle margin.

  • Formula: Spread = Price charged to buyer − Payout to carrier
  • Why it matters: Increased spread means more revenue retained per vehicle without changing volume.
  • Impact: Small per-unit improvements to spread multiply significantly across total transport volume — making it a high-leverage lever even when individual gains appear modest.

Roadmapped levers: Direct Dispatch agreements with lower carrier payouts, Buy It Now button (faster assignment at a slightly lower payout), faster job pickup (payout increases as jobs age on the board, so faster pickup = better spread).

10.3

Cycle Time

The time elapsed from when a buyer requests transport to when the vehicle is delivered.

  • Formula: Cycle Time = Date vehicle delivered − Date transport requested by buyer
  • Why it matters: NPS data shows 50% of buyer take rate is driven by price, 50% by cycle time (half expectations, half actual speed). Picking up from seller lots within 7 days is a key driver of seller retention. Lower cycle time attracts more buyers and sellers to the marketplace.
  • Relationship to other KPIs: Faster cycle time improves take rate and spread simultaneously — the exact relationship is still being quantified.

Roadmapped levers: more direct dispatching to carriers, pricing adjustments for aged requests, carrier staging caps, SLAs for pickup and delivery, Buy It Now button, better Load Board search.

10.4

Combined Business Model

Take Rate and Spread together define Gross Margin per Auction Sold (GM/A), the clearest measure of transport's financial health.

  • GM/A = Take Rate × Spread
  • Gross Margin = Take Rate × Total Auctions × Spread
  • Company impact: Because the business is valued at a high revenue multiple, improvements to transport's gross margin have an outsized effect on overall company valuation.

Transport Promotions on Auction Search

A buyer-facing initiative that surfaces transport promotional pricing directly on the Search Results Page (SRP) listing card — before a buyer clicks into a Vehicle Detail Page (VDP). Launched March 2026.

Source: Internal press release / FAQ document — "Transport Promotions on Auctions Search" (March 17, 2026).
11.1

The Problem

Transport quotes are only accessible after a buyer clicks into a VDP and scrolls to the transport section. This means promotional transport pricing is invisible at the browse layer — the moment when most buying decisions are made. Buyers use distance filters as a rough proxy for transport cost, but these don't account for vehicle size, geography, or promotional pricing.

Previous seller-side transport promotions failed to move conversion because buyers had no awareness of the discount until deep in the funnel, if at all.

11.2

The Solution: Transport Promotion Badge

A badge (e.g. "20% Off Transport") shown directly on the listing card in search results. Buyers see the discounted transport cost before clicking in, removing friction at the earliest point of the buying decision.

11.3

Territory Targeting Strategy

The initiative is targeted at low-performing territories, not rolled out universally. Territory selection uses two overlap signals from marketplace performance analysis:

  • Of 39 territories below 50% UST, 16 (41%) are also below 50% transport attach — struggling on both dimensions simultaneously.
  • Of 50 territories below 50% transport attach, 16 (32%) are also below 50% UST.

Phase 1 criteria: Sell-through rate below 50% (~10pts below average) AND transport attach above 50%. These markets have proven buyer interest in transport but underperform on auction conversion — the cleanest test population to isolate whether the badge moves sell-through without confounding attach issues.

Phase 2 territory selection will be determined based on Phase 1 results, driven by the badge's impact on sell-through and bidding engagement before broadening scope.

12.3

Product Roadmap

Since launch, only minor improvements have shipped. Several major updates are planned to improve the shipper experience and ease of ordering.

  • Multi-vehicle ordering — Shippers can create one order for multiple vehicles from the same pickup to the same delivery. One of the most highly requested features. Also unlocks physical auction transport and rooftop shuffling.
  • Gate pass upload — Shippers can upload gate passes when creating orders. Required to unlock physical and digital auction transport use cases.
  • Address selection & management — Select pickup/delivery addresses from historical orders instead of re-entering manually each time.
  • Real-time status updates — ~50% of orders will have real-time pickup and delivery info from the carrier app. Triggers email, text, and in-app notifications (opt-in).

Physical auction theme: ~30%–50% of off platform orders currently come from physical auction contexts. TAM for physical auction transport requests is estimated at 10M/year.

Sales Strategy

13.1

Auction (In-App)

The most standard and highest-volume scenario. When a buyer wins a vehicle on ACV Auctions and selects "Yes" to ACV Transport during the checkout flow, the system automatically creates the transport order. No manual intervention is needed. Carrier payments flow through Salesforce → Netsuite Scripts.

13.2

Out of App / After Auction

A buyer initially selects "No" to transport at checkout but later changes their mind. The order is created manually by an Ops teammate or directly by the dealer in the Transport Hub. If requested more than 24 hours after the auction ends, an After Auction fee may apply.

13.3

Unwind / ACV Return

Triggered when a completed vehicle sale needs to be reversed. The original buyer becomes the seller, and the original seller becomes the buyer. Transport is used to return the vehicle to the original seller's location. Special handling and communication are often required due to the complexity of reversing a finalized transaction.

13.4

Marshaling vs. Lot Sweep

These two order types are often confused but occur at different points in the vehicle lifecycle:

  • Marshaling — Vehicle moved before it sells. Seller's lot → ACV-owned lot. Allows ACV to hold the vehicle and offer reconditioning, imaging, and other services. Improves sale speed and quality; reduces burden on sellers to store unsold inventory.
  • Lot Sweep — Vehicle moved after it sells. Seller's lot → ACV-owned location. Lets the seller quickly remove inventory; carrier doesn't need to coordinate directly with the seller's lot for pickup.
13.5

Commercial Pass Through

Used for inbound transportation from a seller's location to an ACV-owned facility — primarily the Houston Greenfield launch. Typically associated with bulk inbound or corporate consignment programs. No invoice is created or sent to the buyer within the first 24 hours; not invoiced through normal systems — manually processed through TAP.

13.6

Non-Captive / Off Platform

A dealer uses ACV to transport a vehicle they did not purchase on ACV — acquired through another auction or sale channel. ACV is acting purely as a transport provider. This is the order type that powers the Off Platform Transport product (Transport Anytime). Can be created by Ops or self-served by the dealer via the Transport Hub.

Data quality note: Some Off Platform orders are mis-labeled. RC users self-servicing inbound transport via the portal should be classified as Marshaling — dealer IDs are stored internally for intra-company accounting purposes.
13.7

Ship and Bill (Future)

Does not currently exist. A transport order is created and dispatched immediately, with the buyer invoiced after the fact. Designed for time-sensitive situations where transport needs to be secured before payment is confirmed. Buyer cancellation is not allowed for this order type. Most likely use case: abandoned vehicle escalation — buyer won an auction but failed to arrange pickup.

Is it surfaced in the Transport Hub, sent via email, or both? At what point in the order lifecycle does the dealer receive it (at booking, at pickup, at delivery)? Does the invoice format differ between Auction Transport and Off-Platform orders? Are there separate line items for base transport price, After Auction fees, or surcharges? Can dealers download or export invoices from the hub?
Section 14

Seller Required Transport — Deep Dive

Launched March 1, 2023. A seller opt-in program that allows sellers to mandate ACV Transport for the vehicles they auction — meaning buyers cannot arrange their own pickup. See Section 2.4 for the product overview; this section covers the rationale, data, target segments, financial projections, and GTM approach.

Source: Internal "Seller Required Transport" press release and internal FAQ (March 2023). Financial forecasts are 2023 projections.
14.1

The Problem: Buyer-Arranged Transport Failures

When buyers arrange their own transport instead of using ACV, the results are significantly worse for sellers:

  • Buyers who arrange their own transport are 5× more likely to have significant pickup delays.
  • Issues take 2.5× longer to resolve when reported under buyer-arranged transport.
  • Abandoned vehicle rate: ~3% for buyer-arranged vs. ~0.6% for ACV Transport.
  • Abandoned cases resolved in ~9 days for buyer-arranged vs. ~3.5 days for ACV Transport.

The problem is amplified for vehicles launched from residential addresses — consumer trade-ins picked up from private homes. Delays at residential locations damage the seller's reputation with end consumers for problems entirely outside the seller's control. Lot Sweep (moving vehicles to ACV storage) is the current alternative, but it is expensive and logistically complex at scale due to local tow agreements and storage requirements.

14.2

How It Works

  • Sellers opt in through their Territory Manager.
  • Can mandate ACV Transport for all vehicles they launch, or only vehicles launched from residential addresses.
  • ACV's dispatcher team finds the best carrier and resolves any issues directly — the seller doesn't need to manage it.
14.3

Target Customer Segments

Four segments were identified at launch, each with 2023 volume forecasts:

Segment Description 2023 Forecast
Residential address sellers Existing sellers (e.g. CarBuyerUSA, SwapALease, AllCars) who have said they could double volume if ACV fixed buyer-arranged logistics issues 300–800 units
New OEM & Channel partners Partners onboarding in 2023 who primarily launch from residential addresses — mandated transport required to protect consumer experience 400–1,200 units
Lot Sweep partners Sellers already enrolled in Lot Sweep who want inventory off their lots fast — mandated transport as a cheaper alternative to storage 1,000–2,000 units
High abandoned rate sellers Sellers with >15% abandoned auction rate; ~1,200 vehicles/month sold by this group in 2022; most sensitive to pickup delays 240–720 units

Current attach rate is ~50%, so mandating transport creates a potential 50% attach increase for enrolled seller segments. Projections do not include the potential negative impact on sell-through rate (STR). 14.5

Risks

  • Seller interest: Will sellers opt in? Research needed on appetite among high-abandoned-rate dealers specifically.
  • Buyer reaction: Will buyers bid on auctions where they can't arrange their own transport? 86% of active ACV dealers have used ACV Transport at least once, suggesting comfort with the service if mandated.

14.6

Due to the risk of negatively impacting the auctions marketplace, the rollout is slow and seller-by-seller:

  1. One month before launch: marketing partner sends announcement + FAQs to all potentially impacted buyers and sellers.
  2. Start with Territory Managers of residential address sellers (CarBuyerUSA, SwapALease, AllCars) and enable the product for those sellers first.
  3. A/B test: mandate transport for half of auctions from these sellers to get a clean STR comparison.
  4. Monitor buyer sentiment and behavior closely with TMs and IST throughout.
  5. If STR results are promising, expand — but cap growth at no more than 700 new mandated auctions per month to manage risk.
Section 15

Marketplace Transport Visibility — Phased Proposal

A three-tier product proposal built around a single thesis: surface transport economics earlier in the buying decision flow, where they can actually influence behavior. Each tier builds on the previous one — from a simple signal on browse, to full landed cost transparency, to proactive cross-market recommendations.

Source: Internal "Transport <> Marketplace Visibility — Phased Proposal." Tier 1 is the Transport Promotion Badge initiative already detailed in Section 11. This section focuses on the strategic framing and Tiers 2 and 3.
15.1

The Problem

Dealers make cross-market buying decisions without seeing the full economics of a vehicle at the point of decision. A favorable transport condition — an active promo, a short lane, a low-cost corridor — may exist, but it's only discoverable by navigating to the VDP and manually doing the math.

The gap isn't that transport cost is blocking dealers. It's that the value of a favorable transport situation is invisible at the moment it could drive a decision. Dealers are estimating, ignoring the variable entirely, or passing on vehicles they would have bid on if the economics had been legible upfront.

Competitive context: OpenLane surfaces total landed cost, but only at bid initiation — not at browse. No digital auction platform currently surfaces transport value at the listing level. Doing so at browse would be an industry-first capability that dealers have explicitly asked for.

15.2

Tier 1 — Transport Discount Badge

A badge (e.g. "20% Off Transport" or "$500 Transport Credit") surfaced directly on listing cards on the Search Results Page. Targets territories with low sell-through AND low cross-market bid rate despite sufficient cross-market inventory — where the supply exists but dealers aren't reaching for it.

Full detail in Section 11. Key metrics: badge CTR vs. non-badged, VDP view rate, bid rate, time-to-first-bid, and UST in target territories.

Core question: Do dealers notice and respond to transport cost signals on the SRP? Does badge placement drive measurable lift without cheapening the platform?

15.3

Tier 2 — Total Landing Cost (TLC) Calculator

Hypothesis: Without seeing total landed cost inline, dealers are either estimating cross-market vehicle economics in their head or skipping the mental math entirely. The current industry standard surfaces TLC only at bid initiation. Making TLC legible at browse — before a dealer has decided whether a vehicle is worth pursuing — would be a step beyond what any current digital auction offers, and will increase bid confidence and cross-market bid volume, particularly on vehicles where the landed economics are competitive with local options.

Feature scope:

  • Zip code input (or browser geolocation), persisted per user session and account.
  • TLC = bid price + estimated transport + applicable fees.
  • Shown inline on vehicle cards when TLC is competitive with or better than local comparable options; available on-demand on the VDP for all vehicles.
  • No recommendation yet — purely informational at this tier.

Technical dependency: Latency of cost calculation at scale — must be near-real-time on listing scroll.

What we're testing:

  • Do dealers adopt and use the location input? (Activation rate)
  • Does seeing TLC at browse increase bid confidence? (Bids per session, win rate)

Success metrics: Feature activation rate (dealers who set a location); cross-market bid rate for activated users vs. control.

15.4

Tier 3 — Long-Distance Recommendations

Hypothesis: Proactively surfacing vehicles where total landed cost is lower than comparable local options will unlock latent buying intent and expand the effective market for sellers.

Feature scope:

  • Recommend vehicles from outside the dealer's distance filters where TLC is competitive with local options for the same make/model/condition band.
  • Surface as a dedicated, toggleable module labeled "Best Value Beyond Your Market."
  • Include delta vs. local equivalent — e.g., "cheaper landed than nearest comparable" with a specific savings amount shown.

Algorithmic inputs: vehicle comparables (make/model/year/trim/condition/mileage), dealer purchase history and preferences, TLC = bid estimate + transport by lane + fees, sell-through velocity of recommended vehicles.

What we're testing:

  • Do recommendations drive action or get ignored?
  • Does the recommendation logic actually identify good deals — not just cheap-to-ship lemons?
  • Does this cannibalize local sales or expand total platform GMV?

Success metrics: Recommendation CTR, recommendation-to-bid conversion, incremental GMV.

15.5

Cross-Tier Risk Flags

  • Badge gaming: Dealers selectively bid only on badged vehicles, distorting the signal and reducing value of non-badged inventory.
  • Recommendation quality: The algorithm surfaces low-quality vehicles that simply have cheap transport — misleading dealers into bad purchases.
  • Cannibalization: Cross-market wins pull buyers away from local inventory, reducing local sell-through and net platform GMV.
Section 16

Vehicle Documents

A reference for the documents involved in the pickup and delivery of a transport job — who generates them, who receives them, and when they appear.

16.1

Vehicle Release Slip (Gate Pass / Pickup Slip)

The primary authorization document for vehicle pickup. Each release slip is tied to a unique Release Slip Identifier (RSI), embedded as a QR code that is scanned or exchanged at the physical pickup. One RSI corresponds to one row in the admin table. A single auction may have multiple RSIs over its lifetime as slips are cancelled and regenerated.

Three Slip Types
  • Carrier Release Slip — Issued to the assigned carrier/transporter. Contains a real QR code. Authorizes the carrier to take physical possession of the vehicle at the pickup location.
  • Buyer Release Slip — Issued to the winning buyer when they arrange their own pickup (Non-ACV Transport / Self-Pickup). Contains a real QR code. Gated behind payment clearance — only available after the Payments team marks the auction as releasable.
  • Buyer Receipt ("dummy" slip) — Issued to the buyer when ACV Transport is selected at checkout. Looks visually similar to a release slip but does not contain a QR code. Includes a bold red disclaimer that it cannot be used to pick up a vehicle. This is intentional: the carrier is the authorized pickup party, not the buyer.
Creation Workflow — ACV Transport Selected at Checkout
  • When a buyer selects ACV Transport for a won auction, the carrier receives a real release slip with a unique QR code upon carrier assignment.
  • The buyer receives a Buyer Receipt (dummy slip, no QR code) — the carrier is the authorized pickup party.
Creation Workflow — Auction Marked "Releasable" (Non-ACV Transport / Self-Pickup)
  • The buyer's real release slip is gated behind payment clearance.
  • Once the Payments team marks the auction as releasable, a real Buyer Release Slip (with QR code) becomes available.
  • Ops can then download and email the slip to the buyer directly from the admin tool.
Cancellation Scenarios
  • Transport order cancelled by ACV: The carrier's active release slip is automatically cancelled. A new buyer release slip is generated, but only after the auction is marked releasable by Payments. Until payment clears, the buyer release slip row will not appear.
  • Transport order cancelled by the transporter: The carrier's active release slip is automatically cancelled. The buyer's slip is not affected. When a new carrier books the job, they receive a brand new unique release slip (new RSI and QR code).
Admin Access
  • Direct URL: transport-admin-v*.acvauctions.com/vehicle-release-slips
  • Via Okta: Transport Admin → Hamburger menu → Carrier Management → Vehicle Release Slips
  • Access required: Transport Admin App → Release Slip User role
Ops Capabilities
  • Ops with Release Slip User access can invalidate an active release slip, regenerate a new one, and download a release slip.
  • Ops can email a release slip to the buyer — only available after the slip reaches "releasable" status.
  • The event log in the admin table tracks external user actions against the QR code (scanned, exchanged).
QR Code Hotline (live pickup issues): 716-923-7923 — for QR code problems during an active physical pickup exchange.
16.2

eBOL (Electronic Bill of Lading)

The electronic delivery receipt uploaded by the carrier after delivering the vehicle. Required for carrier payment. Serves as the legal record of condition at delivery. Carriers upload the eBOL through the Loadboard after marking a job as delivered.

16.3

Dispatch Sheet

The ACV–carrier agreement document, available for carrier download once a job is Dispatched or Picked Up. Covers vehicle details, pickup/delivery locations, and payout terms.

16.4

Gate Pass (Dealer Upload)

For off-platform orders, dealers may be required to upload a Gate Pass when creating the order. This is distinct from the ACV-generated Release Slip — it is a dealer-provided document that conditionally unlocks certain pickup scenarios. Whether it is required depends on the pickup location's requirements.

⚠ To investigate: What are the exact conditions that require a dealer-uploaded Gate Pass for off-platform orders? How is it surfaced in the Transport Hub? What happens if it is not uploaded — is the job blocked from dispatch?
Section 17

Pickup Security — v2

A redesigned vehicle pickup authorization system addressing two problems simultaneously: a web spoofing vulnerability in the prior technical approach, and chronically low adoption of the release process among lot managers and carriers.

17.1

Goals

  1. Make the process as secure as required by auto industry threat standards
  2. Make the transport process with ACV seamless for dealers
  3. Make the transport process with ACV seamless for carriers
  4. Vehicles sold on ACV Marketplace must be safe for all dealers
  5. Vehicles not sold on ACV Marketplace should be safe for the buyer dealer
17.2

Scenarios Covered

  • In-App Transport — Known buyer, known seller, known carrier. All parties registered on platform.
  • Buyer-Arranged Transport — Known buyer, known seller, unknown carrier. Buyer provides driver contact; driver verifies device via OTP.
  • Off-Platform Transport In Progress — Known buyer, unknown seller. Seller not registered on platform; release confirmed via 2-digit code over email or SMS.

Scenarios explicitly out of scope:

  • Pickup from physical auctions — requires a separate verification approach not addressed here
  • Marshalling / First-leg orders — vehicle movement prior to carrier handoff handled by a different process
  • Unwinds — to be defined
17.3

Lot Manager Registration

Two-phase setup — phone number must be registered before device registration can occur.

  1. Phone number registration: A Back Office User registers the lot manager's phone number in Marketplace BackOffice → MBO stores it and fires a "lot manager phone registered" event → Vehicle Release Service (VRS) registers the user's phone number
  2. Device registration (can occur in any order once phone number is registered): Lot Manager opens Vehicle Release App → enters phone number → VRS requests OTP via SMS → LM enters OTP → VRS verifies OTP and device details → device registered and linked to the Lot Manager
If OTP is invalid: verification failure shown, retry or resend OTP prompted.
17.4

In-App ACV Transport Flow

All parties registered and verified. Carrier receives a digital release slip in the Carrier App.

  1. VRS pre-assigns job and release slip to the Vehicle Release App (Lot Manager's trusted device)
  2. Driver enters the geofenced pickup area → app notifies VRS → VRS unlocks the pickup code request
  3. Driver requests pickup via the Transport App → VRS instructs the app to display the NFC tap device prompt
  4. Driver taps the NFC device (Vehicle Release App on Lot Manager's device)
  5. Vehicle Release App sends verification request to VRS
  6. Authorized: VRS confirms release → both LM and driver receive release confirmation
  7. Not authorized: LM shown "Not permitted to release this vehicle — Contact ACV if issue"
17.5

Buyer-Arranged Transport Flow

Buyer uses a driver not registered on the platform. Buyer provides a trusted email or phone number for the driver.

  1. Buyer authorizes release → VRS sends buyer a short code → buyer shares short code directly with driver
  2. Driver installs ACV Transport App (if not already installed) → opens app → requests device verification
  3. VRS sends OTP to driver's phone number via SMS → driver enters OTP → VRS verifies OTP and device details → device verified
  4. Driver enters the short code in the app → VRS submits → job and release slip assigned to driver's device
  5. Driver enters geofenced area → same NFC tap and release flow as In-App ACV Transport (Section 17.4)
17.6

Off-Platform Transport Flow

Seller is not registered on the platform and cannot use the Vehicle Release App. Release is confirmed via a verbal code exchange backed by email or text.

  1. VRS pre-assigns job and release slip (QR code) to the ACV Transport App
  2. Driver enters geofenced pickup area → geo-fence entry notified → pickup code unlocked
  3. Driver requests pickup code → VRS returns QR code + 2-digit code → app displays both to driver
  4. Simultaneously: VRS notifies the seller's contact on file via Email/SMS Notification Service — instructs them to reply with the 2-digit code shown by the driver
  5. Driver shows the 2-digit code to the lot manager verbally
  6. Lot manager replies with the code via email or text → notification service forwards to VRS → VRS validates code and marks vehicle released
  7. VRS confirms release to seller → lot manager instructed to release vehicle to driver → driver's app shows release confirmation
17.7

Device Verification for Carriers Without an Account

Lightweight verification path — no account creation required — used when the carrier is unknown to the platform (Buyer-Arranged scenario):

  1. System generates a unique link tied to the specific order
  2. Link sent to the carrier's trusted email or phone number (provided by the buyer)
  3. Carrier opens the link → prompted to install the Carrier App if not already installed
  4. Carrier enters their phone number to begin verification
  5. OTP sent via SMS
  6. Carrier enters OTP to complete verification
  7. Carrier's device is linked to the job and they receive the release slip
17.8

Process Integrity Controls

Three mechanisms that ensure the release process is followed correctly at every handoff:

  • Code swap — The 2-digit code must be exchanged between the carrier and the release authority (lot manager or seller representative). Creates shared confirmation that both parties were physically present at handoff.
  • Registered carriers only — Pickup is restricted to carriers with a verified device linked to the specific order. No anonymous pickups.
  • Geofencing — A pickup code can only be generated when the carrier is physically within the geofenced area of the pickup address. Prevents remote code generation.
